## Persistent SFTP resume and encrypted SSH keys — 2026-10-11

Compiled package 0.2.0 preserves the headless engine and adds durable native SFTP transfer jobs. **Pause transfer** retains a private partial; **Pending transfers…** lists the endpoint's jobs and offers explicit Resume or Discard. Every native upload/download uses this journal. Resume verifies the original authenticated host key, profile binding, source metadata and complete source digest, then compares the retained partial prefix before appending. It verifies the complete staged SHA-256 and original destination before commit. Changed source, destination, host key, profile, symlink, partial prefix or permissions are refused while existing data is preserved. Profile edits keep affected jobs visible with disabled actions until original settings are restored.

Overwrites preserve the reviewed original in a unique remote backup until verified commit cleanup. The commit phase is journaled before renames. A reconnect recovers a completed rename whose reply was lost, restores an original backup if the partial was not delivered, or finishes cleanup of an already delivered file. Discard requires the original host identity for remote mutations and recovers an interrupted original backup before removing owned partials. The journal uses owned nonsymlink 0700 directories, single-link 0600 records, atomic write/fsync/rename, bounded typed IDs, 32 KiB records, at most 128 jobs and 32 GiB files. Stable per-job lock inodes prevent competing workers from splitting ownership across a recreated lock. Completed local journal removal is directory-synced.

Only the reference is saved in metadata; the private entry clears after storage. Native SFTP supplies the retrieved passphrase to libssh2 and wipes its key/passphrase buffers after authentication.
